# Phase 6 — Abstractive legal summarization

Generate one summary per legal case. The submission contains one `{"id": "...", "summary": "..."}` record per test document. BERTScore F1 is the primary metric, with ROUGE-1 and ROUGE-L as secondary metrics.

The causal runs pack up to 1,536 document tokens into an instruction prompt and mask the prompt from the next-token loss. Model 2 encodes up to 1,408 source tokens and trains its causal decoder with cross-attention. The recorded Model 1 test export uses greedy decoding, a 384-new-token limit, a repetition penalty, and token 4-gram blocking.

## Run order

1. Attach the relevant asset ZIP from the table, or provide the matching Phase 1 checkpoints through `MODEL_DIR` in the single-model notebooks or `MODEL_DIRS` in the multi-model notebooks. Set `DATA_ROOT` to the folder containing `Train/train.json` and `Test/test.json` if you are supplying the official files yourself. Run setup, the grouped split audit, token preparation, and shared training and generation helpers.
2. **Full fine-tuning.** Run section 8 for Model 1 or section 9 for Model 3. Run capacity and the small-sample check before **Train or resume**, then run **Full held-out evaluation**, **Analysis exports**, and **Test submission**. Outputs are separated by run name under `/kaggle/working/phase6_full_finetuning/runs/`.
3. **Model 1 LoRMA or Model 3 LoRA.** In the corresponding notebook, run sections 8–14 after setup. This runs the functional and capacity checks, trains or resumes, evaluates on the full held-out split, and exports the test ZIP. Each notebook uses its own `OUTPUT_ROOT/run`.
4. **Model 2 adapters and Model 4 student.** Run section 8 for the encoder–decoder adapter experiment. For distillation, the bundled assets provide a trained teacher. A separately attached teacher export needs its `teacher_info.json` and matching `best.pt` for automatic discovery. Set `TEACHER_RUN_NAME = 'model3_lora'` to reproduce the archived teacher, then run section 9 to cache its training summaries and section 10 for student training, validation, and export.
5. Resume with a compatible `latest.pt` and the original run metadata. For local scoring, use the predictions from **Full held-out evaluation** and the matching generated validation truth JSON. The test export prints the path to the archive to submit.

The [run manifest](run_manifest.json) records those sources, the full dev ROUGE scores, and hashes for the original checkpoints and predictions.
